# Research notes: protocol core (P1/P2 delivery protocol)

- **Scope:** `bin/ak`, `docs/{delivery-protocol,reporting-model,roles-model,supervision-model,safety-model,herdr-workflow,primary-agent-model}.md`, `tests/{test-inbox-protocol,test-ladder-correlation}.sh`, and fixes to `tests/test-p0-delivery.sh`. No `extensions/`, no `shared.md`, no `install.sh`.
- **Building on:** P0 (`zyomqrwy` + `p0-verify`) made the transport honest (confirmed acceptance). This change makes the *message* durable, acknowledged, retried with a ceiling, correlated, and ordered.

## What was implemented

1. **Durable steering inbox** — `.agent-kit/crew/<slug>/inbox/NNN.msg` (+ `handled/`), `schema=ak-inbox.v1` envelope (`id`, `at`, `from=primary`, `delivery`, `--` + verbatim body). Temp-write + atomic `rename`; `%03d` sequence allocated under the per-crew lock scanning both `inbox/` and `handled/` so numbers are never reused. Body read-back skips to `--` then reads verbatim (round-trips newlines, `--`, backticks, `$(...)`, quotes, tabs).
2. **Doorbell, not payload** — `ak crew-send` writes the durable record then rings one constant, payload-free, inert line (`: ` POSIX no-op prefix). Its exit status reflects the record write, never the keystroke.
3. **Acknowledgement** — `ak ack [slug] [seq|path]` moves the record to `handled/` (the move is the ack); no arg acks all in numeric order. The generated worker brief states the contract and the exact `ak ack <seq>` command.
4. **Bounded re-ring ladder + escalation** — `AK_INBOX_GRACE_SECS` (90) / `AK_INBOX_RING_MAX` (3); ring-state TSV (`seq count epoch`), escalation markers under `inbox/.escalated/<seq>`; fire-and-forget excluded; liveness probed before typing (positively dead/missing escalates directly, never typed). Observable via `ak crew-audit`; driven by `ak crew-sweep <slug>`.
5. **Correlation** — `ak crew-send --expect-reply` arms a durable `.agent-kit/crew/<slug>/pending/<corr>` (`schema=ak-pending-reply.v1`, `corr=<16 hex>`, `phase`) *before* delivery; the corr is embedded in the body; `ak done`/`crew-report` resolve it only via a correlated `corr=<hex>` echo. `ak crew-sweep` sends exactly one recovery request (`waiting -> recovery-sent`) then escalates once (`recovery-sent -> escalated`), never looping.
6. **Authoritative lifecycle state** — `state` file `schema=ak-crew-state.v1` with `spawning/running/reported/done/failed`, compare-and-swap transitions under the per-crew lock; illegal transitions fail loudly. Live agent status is a separate, labelled probe.
7. **Locking** — `.agent-kit/locks/crew-<slug>.lock` around state transitions, inbox sequence allocation, ring-state, ack, and `crew-finish`. `crew-finish` refuses while a report is in flight and distinguishes missing vs dirty worktree.
8. **Spawn metadata** — `meta` gains `title=<one-line purpose>` (derived from the brief `# Objective`) and `session_id=<token>` (from `.agent-kit/primary`, regenerated by `ak primary-set`), written before the tab is created.
9. **Framing** — primary-bound wakes are flattened to one line and prefixed `[crew <slug>]`; worker text cannot masquerade as a user turn.
10. **F4/F5 resolution** — `crew-report --note` records non-terminal notes without flipping state; `undelivered_at` is a single authoritative value (last-wins).
11. **Test hygiene (D3)** — both P0 tests now close their throwaway Herdr workspace; no workspace leak observed.

## Env knobs and defaults

| Env | Default | Meaning |
|---|---|---|
| `AK_INBOX_GRACE_SECS` | 90 | re-ring period per unacked ack-required record |
| `AK_INBOX_RING_MAX` | 3 | max ring attempts before escalation |
| `AK_WAKE_ACCEPT_TIMEOUT` | 8000 | ms to confirm a woken agent enters `working` |
| `AK_CREW_STARTUP_TIMEOUT` | 120000 | ms overall startup-prompt acceptance deadline |
| `AK_CREW_READY_TIMEOUT` | 15000 | ms to wait for input-ready pane |
| `AK_DEBUG_WAKE` | unset | path; append each framed wake + doorbell line (diagnostic/test) |
| `AK_INBOX_RING_OK` | unset | test seam; treat doorbell ring as a successful keystroke |

## Exit-code contract (per command)

- `crew-send` → 0 record written (or idempotent re-send recognised); 1 record write failed; 2 usage. Doorbell never changes the code.
- `ak ack` → 0 (acked, or nothing to ack); 1 unknown crew/record; 2 usage.
- `crew-sweep` → 0; 1 unknown crew; 2 usage.
- `crew-report` → 0 report written + wake confirmed; backend code (1/2) if wake unconfirmed after write (with `undelivered_at`); 1 report rejected (done/failed crew); 2 usage.
- `crew-report --note` → 0 note recorded, state unchanged.
- `crew-finish` → 0; 1 refusal (not reported/done, failed without `--abandon`, missing/dirty worktree, missing report); 2 usage. Missing worktree reported distinctly from dirty.
- `crew-spawn` → 0 only on `running`; 1 otherwise with `state=failed` + recovery command; 2 usage.

## What remains open (for the Go port)

- **`report.template.md`** and **`primary_notify`** remain dead artifacts in bash (not removed to keep the diff reviewable); the Go port deletes them (§9 of the port plan).
- **No `fsync`.** Atomicity is temp+rename / O_APPEND single-write; a host crash can still lose the tail of append-only files (`chat.log`, `cost.tsv`, `progress.tsv`) and a just-renamed file's directory entry. The Go port adds `f.Sync()` + directory sync.
- **Stale-lock reclamation.** The bash `mkdir` lock has no staleness recovery; a crashed writer leaves a lock until manual removal (the Go port records pid/time and reclaims).
- **`ak reply`/`done` still use the spawn-time `primary_target`** snapshot from the role marker (the live primary registration is read only by `crew_report_core`). The Go port resolves the primary at reply time.
- **`primary-set` crew-refusal** still reads `meta` files only; the Go port reads the store (meta-less crews refused).
- **No watcher.** The re-ring ladder and pending-reply recovery are synchronous (driven by `ak crew-sweep`), not a background service — consistent with the port plan's "Delivery is a synchronous bounded-retry call inside a CLI command, not a background service."
